# Steam 截图管理与 WebDAV 同步调研

日期：2026-09-20。范围：资料调研、现有项目核查、当前电脑只读检查、方案建议。未开发或部署程序。

## 做了什么

核查 Steam 截图目录、游戏列表与认证 API、浏览器读本机文件的边界、WebDAV 传输限制；阅读三个截图工具和 rclone 的资料及部分源码。完整结果见 [调研与建议方案](../../.research/steam-screenshots-2026-09-20.md)。

只读检测到本机 Steam 安装于 `C:/LocalSpace/softwares/Steam`，读取了游戏库清单和安装清单中的 AppID/name；一个 userdata 用户目录下未发现标准 760 截图数据，查找的用户配置中未发现自定义截图路径字段。因此未形成真实截图采集、上传或跨电脑恢复的验证证据。

## 建议与原因

建议本地桌面应用直接绑定 WebDAV，NAS 可选。原件复制到独立图库，按游戏浏览，新增内容跨端汇集，本地删除不传播远端删除。Steam 登录用于后续游戏信息增强，不作为采集前置条件。

第一版以 Windows、离线采集、按游戏管理、WebDAV 上传校验和新机恢复为范围建议。写回 Steam 原生截图索引、录像、存档和服务器业务系统未纳入。用户尚未确认实施范围。

## 踩过的坑与核查纠偏

1. 查询项目维护信息时，尝试 GitHub 公共 API 返回原始错误 `API rate limit exceeded`。最初计划通过 API 核实最后提交时间，但响应失败且各字段为空，不能把空值说成项目停更。改为阅读公开仓库和原始源码，保留维护时间未核实的边界。
2. 不能将“类似截图工具支持 Steam”推断成完整覆盖截图格式。实际查看 Games Screenshot Manager 的 Steam 扫描代码，只匹配 `.jpg`；Valve 官方更新已说明支持 HDR AVIF，因此方案加入原样保存高质量副本和不支持预览时仍可备份的要求。
3. Steam Screenshot Organizer 名称容易令人以为只是收集副本。源码实际调用 `fs::rename` 原地移动，且 Windows 有默认路径硬编码。本轮只读核查，未运行该程序，不把它直接推荐为原件备份工具。
4. 浏览器页面不能仅凭 Steam 登录就扫描访问者硬盘；Steam OpenID 只用于身份认证。网页授权选目录和本机常驻客户端是不同能力，方案据此以客户端为主。

上述为调研中发现的限制，不是本项目已发生的数据事故。未发现或虚构同步测试结果。
