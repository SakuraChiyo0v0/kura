# 2026-09-24 服务端加"框选目录"页面（files-admin）

## 起因

用户："我们要不要服务端加个界面，实现手动框选目录" → 选定方案 B：
**挂在网关后面（Authelia 认证）、只能选白名单根、变更留痕；每次勾选后重建容器，WebDAV 断 1~2 秒。**

## 先做的决定性实验（决定了整个设计）

"改配置能不能热生效"直接决定界面值不值得做，所以先用一次性容器实测：

| 实验 | 结果 |
|-|-|
| 改 `--filter-from` 指向的文件（`--dir-cache-time 1s`，等 9 秒） | **不生效**（还是旧规则） |
| 对照组：重启同一个容器 | **立刻生效** |

**结论：rclone 的过滤器是启动时读一次的**（不是目录缓存造成的假象 —— 把缓存压到 1 秒仍然不变）。
所以"保存勾选"之后必须有一步"重启"，这也决定了下面那个关键的架构选择。

顺带试出两条会坑人的 rclone 语义（都写进知识库了）：

1. `--exclude` / `+` 规则里，**只有 `/路径/**` 那一版真的生效**，只写目录名等于没写
   （实测：只写目录名时列表里照样看得见、直连也 207）；
2. **父目录不必额外放行**：只要某个子项被 include，路径上的目录就会出现在列表里、可以直接导航进去
   （实测：只写 `+ /volume1/<媒体目录>/**`，根列表就显示了 `volume1/`，进去只见放行的那个目录、其余被挡）。

## 最终形态

```
浏览器 → 网关（Authelia）→ files-admin 页面     ← 勾选，写 selection.json + filters.txt
                                 ↓（文件变化）
                          宿主 systemd path 单元  ← docker restart nas-webdav
                                 ↓
                              nas-webdav (rclone) ← 按新规则决定"看得到什么"
```

新增组件 `server/files-admin/`（Go，单文件二进制；容器只挂 `sso-net`、不发布任何端口）：

- `GET /` 页面：懒加载目录树 + 勾选 + 保存 + 生效状态（沿用 nas-mirror 状态页那套"服务端渲染 + 无前端库"）；
- `GET /api/tree` 列白名单根之内的子目录（跳过系统项）；`GET /api/state` 回状态；
  `POST /api/save` 校验 → `selection.json` → 生成 `filters.txt` → 写 `audit.log`；
- **勾选模型是白名单**：生成的规则三段式 = 先钉死系统项（硬编码，界面勾不到）→ 逐条放行勾选目录
  → `- /**` 兜底。没勾的一律不可见。

`nas-webdav` 的那一长串 `--exclude` 全部删掉，改成 `--filter-from /cfg/filters.txt`
（排除规则搬进生成器，`@*`/`.fscrypt`/`lost+found` 依然挡住，只是现在从界面也勾不到）。

## 三个刻意的架构选择

1. **不给这个 Web 服务 docker 权限**。重启容器需要 docker 权限，而 docker 权限等于 root
   （能起任意容器挂 `/`）。所以"重启"这一步拆给宿主上的 `nas-webdav-apply.path`（systemd path 单元
   监视 `filters.txt` 变化 → `docker restart nas-webdav` → 把结果写进 `apply.status` 供页面显示）。
   这个服务只会**写文件**。
2. **白名单根 + 硬编码系统项**。`/volume1`、`/home` 之外一律拒绝（路径规范化后按归属判断，
   而不是"以 / 开头"这种形态判断 —— 形态可以伪装，归属不能）；`@*`、`.fscrypt`、`lost+found`
   写死在生成器里，界面里根本看不到，所以手滑也暴露不了系统目录。
3. **不加认证层**：容器只挂 `sso-net`、不发布端口，认证复用网关的 Authelia（与其它 11 个服务同一条路）。

## 踩过的坑（这一段最重要）

1. **`filepath` 是错的工具**：路径是**容器里的 POSIX 路径**，用 `filepath.Clean("/volume1")` 在 Windows 上
   会变成 `\volume1`，白名单校验直接失效（单元测试先炸出来了）。改用 `path` + 兼容反斜杠；
   并且把校验依据从"以 / 开头"换成"**是否落在允许的根之内**"。
2. **实验脚本自己写错三次**：① 把 `- /**` 放在规则最前面（应该最后，rclone 先匹配先生效）→ 全挡；
   ② 用 GET 抓目录、却按 PROPFIND 的 `<D:href>` 去 grep → 全空；③ 在容器里用 `wget` 验 PROPFIND。
   三次都让"实验结论"看起来像"功能坏了"。
3. **PowerShell 的 `.Length` 陷阱**：`$page = & curl.exe ...` 得到的是**字符串数组**（按行），
   `.Length` 是**行数**（277）而不是字节数，我据此以为页面被截断了 —— 用 `curl -w %{size_download}` 才是字节数（10866）。
4. **`systemd` 的 `PathChanged` 对"原子替换"是否触发**：本程序写文件是 tmp + rename，
   这点事先无法从文档确定，**靠端到端实测确认**（2 秒内触发）。
5. **rclone 起不来就停摆**：`filters.txt` 缺失或写坏时容器会 `CRITICAL: malformed rule` 起不来，
   所以生成必须原子（先 tmp 再 rename），且首次部署的顺序是"先起 files-admin → 保存一次 → 再切 nas-webdav"。

## 遗留风险

- **符号链接**：rclone 带 `-L`（跟随链接）。挂载边界限制的是"挂进容器的根"，不是"符号链接能指向哪" ——
  数据目录里若存在指向根外（如 `/etc`）的链接，勾选其父目录后会被跟随。这是既有行为，未变。
- **谁都能改**：任何能登录网关的用户都能改暴露面（当前单用户环境）；变更只留痕、不审批。
- **`PathChanged` 与容器重启**：保存 → 重启约 1~2 秒的 WebDAV 中断；重启期间正在传输的文件会失败。
- 页面上的目录树是**懒加载**，深层目录第一次展开要等一下（服务端逐层读目录）。

## 同日升级：模型从"白名单根 + 硬编码系统项"改成"白名单 + 反向排除"

用户上手看了页面后提了三点：① 子项全是灰的看不懂；② 要能开放所有目录（含系统目录）；
③ "然后我再配置，这样就可以自定义了"。于是：

- **去掉两处硬编码**：不再是"只能选 `/volume1`、`/home`"，也不再有"`@*`/`.fscrypt`/`lost+found` 永远挡住"。
  容器改为把整个宿主根只读挂在 `/host`（`--host-prefix /host`），页面因此能列 `/etc`、`@appstore` 等等；
- **三态勾选 + 反向排除**：勾父目录后**再点子目录 = 单独排除**（生成 `- /child/**`）；
  界面上用「放行 / 随上级放行 / 已排除」三个小标签说明状态（这就是用户看不懂的那处）；
- **规则顺序变严**：排除必须排在放行之前（否则被放行吞掉）。这是 rclone 的先匹配先生效语义，
  写进生成器注释与测试（`TestRenderFiltersOrderAndShape` 直接断言三段的先后）；
- 顺手修了布局 bug：断点从 820px 提到 1000px，1136px 宽时右栏不再被挤到截断。

**过程中抓到一个真 bug**：我第一版把"放行会取消排除"写反了方向 ——
写成了"取消放行项**之下**的排除"（那正好把"挖洞"功能删掉了），
正确语义是"放行项落在排除项**之内**时取消那条排除"（`removeAncestorsOrSelf`，不是 `removeUnder`）。
单元测试先炸出来（`排除项应去重保留一条，实际 []`），修完 `TestSaveSelectionIncludeCancelsExclude` 才过。

另一个自摆的乌龙：种子化时我把中文路径写成了 **URL 编码**塞进 JSON 请求体，服务端不解码 → `os.Stat` 找不到 →
保存失败（报错被我 PowerShell 的字符串数组陷阱吞掉了，看起来像成功）。**JSON 体里就是字面路径**。

## 同日第三次：页面整体改版 + 手写规则（并踩了一次自己写的示例的坑）

用户："我觉得可以加一下手写规则，然后整体页面再优化一下，现在有点 low。"

**手写规则**：`selection.json` 增加 `rules` 字段，生成文件分成四段 ——
手写规则（最前，**优先于页面勾选**）→ 自动排除 → 自动放行 → 兜底 `- /**`。
校验只管形态（`+`/`-` 前缀、长度、200 条上限），写错由 rclone 启动时报错，页面「生效状态」显示失败。

**页面改版**：重做了设计体系（色板/间距/阴影/圆角 tokens、状态胶囊、粘性保存条、`beforeunload` 未保存提醒）、
目录树的过滤框与「全部收起」、行状态底色与删除线、右侧清单可滚动+清空、生成结果折叠展示。

**踩的坑（值得单独记）**：我给示例写的是 `- /volume1/@*`，
端到端测"新建一个 `@` 目录会不会被挡住"时得到 **207（没挡住）** ——
这正是我们**之前实测过**的语义：只写目录名不生效，必须写 `/路径/**`。
更糟的是我第一轮的验证探针也错了：探的是 `/volume1/#recycle`（顶层根本没这个目录），
拿到 404 却是"路径不存在"而不是"被过滤" —— **假阳性**。
改用 `/volume1/@*/**` 后：新建 `@probe2` → **404**（连里面的文件直连也 404），
对照组（<媒体目录>、<媒体目录>/#recycle、docker）都是 207。

> 教训：**示例本身就是文档**，写错等于教错；而且"404"要先分清是"被规则挡住"还是"路径不存在"，
> 否则验证会给出假阳性。两条都已写进页面提示、README 与测试。

## 同日第四次：可见性自检（顺带把 `/**` 的机制弄明白了）

用户问"手写规则排在最前、优先于页面勾选，这个怎么理解"，于是加了**可见性自检**：
输一个路径，按最终规则算出可见不可见、以及被哪条规则决定。规则列表与生成文件共用 `buildRules`，
所以自检不会和生效规则算岔。

**做这个功能的过程里连撞三个"我以为"：**

1. **模式按字节遍历 + `QuoteMeta`** → 中文的每个字节被转成 `\xe9` 这类 **rune 转义**（那是 U+00E9，
   不是那个字节），于是**含中文的模式永远匹配不上**。改成按 rune 遍历。单元测试先炸出来的 ——
   而我最初的模式测试只用了 ASCII 路径，正是覆盖漏洞。
2. **`/**` 的语义想错了**：我以为 `/x/**` "只匹配它下面"，翻译成 `.*`（要求后面还有斜杠）。
   实测/机制是 **rclone 的 `**` 匹配零个或多个段**，所以 `/x/**` **也匹配 `/x` 本身** ——
   这才是"只写目录名的规则不生效、必须写 `/**`"背后的原因。
3. **测试里写错预期**：`{"/volume1/@*/**", "/volume1/@appstore", false}` 这条断言正是我第 2 条误解的产物，
   它挂了之后我先怀疑实现、再怀疑模型，最后才确认是**预期错了**。

**验证这一步的自摆乌龙**（都是我的探针，不是功能的问题）：
① `EscapeDataString('/volume1')` 把开头的 `/` 编码成 `%2F` → curl 直接 `000`；
② 参数里已经带了 `%23`，我又 `EscapeUriString` 了一次 → 变成 `%2523` → 得到 404，
差点当成"自检算错"。

**最终判据**（把自检结论与真实状态码逐条对照，10 条真实路径）：

| 路径 | 自检 | 实际 | |
|-|-|-|-|
| `/volume1`、`/volume1/<媒体目录>`、`<部署根>`、`/home`、`/home/<用户A>`、`/volume1/<媒体目录>/#recycle` | 可见 | 207 | ✓ |
| `/volume1/@appstore`、`/volume1/@docker`、`/volume1/.fscrypt`、`/etc` | 不可见 | 404 | ✓ |

> 教训：**"不一致"先怀疑自己的探针**。这一轮两次"不一致"全是探针的 URL 处理错了，
> 而真正被证明是错的，是我对 `/**` 语义的假设 —— 以及把那个假设写进测试的"预期"。
