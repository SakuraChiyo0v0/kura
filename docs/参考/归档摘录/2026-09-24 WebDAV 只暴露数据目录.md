# 2026-09-24 WebDAV 只暴露数据目录（`/home` 与 `/volume1`）

## 起因

用户贴来 rclone 容器日志，满屏：

```
ERROR : rom/bin/X11/X11/X11/X11/X11/X11/X11/X11/X11/which: Listing error: symlink: stat …: no such file or directory
ERROR : usr/bin/rvim: Listing error: symlink: stat /data/usr/bin/rvim: no such file or directory
NOTICE: rom/dev/console: Can't transfer non file/directory
```

## 根因（已确认，两类，都是"跟随符号链接"撞上的）

`nas-webdav` 当时以 **`/` 为根**（`/:/data`）且带 **`-L`（跟随符号链接）**：

1. **自指链接**：`/usr/bin/X11 -> .`（指向自己）⇒ 展开成 `X11/X11/X11/…`；
   `/rom` 是 UGOS 的系统根副本，里面是同一套链接，于是再来一遍；
2. **悬空链接**：`/usr/bin` 下一堆 alternatives（vim、rvim…）目标不存在；`/etc/mtab`、`/etc/rmt` 同理。

rclone 有递归深度上限（不会卡死），但**每展开一层记一条 ERROR**。实测那一轮 **39 条 / 2 分钟**。
这不是故障（WebDAV 一直正常返回 207），但会淹没真正的错误、遍历也慢。

## 先走的弯路：加 `--exclude` 排系统树

用户先选了"保留 `/`、加排除规则"，于是加了一版
`--exclude /rom/** /usr/** /bin/** /sbin/** /lib*/** /proc/** /sys/** /dev/** /run/** /overlay/** /rootfs/** /tmp/**`。
判据（对 `/usr/bin/` 与 `/rom/` 各发一次 PROPFIND，`docker logs --since 2m | grep -c ERROR`）**从 39 变成 0**，
且 WebDAV 根目录列表从 30 项变成 17 项（系统树消失、`etc/home/root/opt/var/ugreen/volume1` 都还在）。

## 最终形态：把"排除"换成"挂载边界"

用户随后一句"**系统树感觉都可以不暴露**"，于是不再打补丁，直接改暴露面：

```yaml
volumes:
  - /volume1:/data/volume1
  - /home:/data/home
command: [serve, webdav, /data, -L, --exclude, /volume1/@docker/**, --addr, ":18005"]
```

- 系统树**根本不在容器里**（连 `/etc/shadow`、`/root` 都看不到）—— 边界从"排除什么"变成"挂载什么"；
- 那批 `--exclude` 与 `/proc /sys /dev` 的 tmpfs 掩码**全部删掉**：它们本来就是为"挂整个 `/`"服务的；
- 只留一条 `--exclude /volume1/@docker/**`（docker 自己的镜像层存储）：**全盘 1410 个悬空链接全在里面**，
  而用户日常会翻的目录全是 0 —— 实测 `/volume1/{<各数据目录>}`
  与 `/home` 的 `find -xtype l` 计数均为 0；- **WebDAV 里的路径没变**：仍然是 `/volume1/…` 与 `/home/…`（原来挂 `/` 时也是这两个路径），
  已映射的盘、写好的脚本都不用改。

## 验证（判据都是实机）

| 检查 | 结果 |
|-|-|
| 根列表 | 只有 `/`、`/home/`、`/volume1/` |
| 数据可读 | `/volume1/` 207、`/home/` 207、`/volume1/<媒体目录>/` 207、`/home/<用户A>/` 207 |
| 系统树不存在 | `/etc/`、`/usr/bin/`、`/rom/` → **404**；容器内 `ls /data` 只有 `home volume1` |
| 日志噪音 | 同一轮探测 `grep -c ERROR` = **0**（改动前 39）；日志只剩两行启动 NOTICE |
| 真能写 | `PUT /volume1/…` → **201**、读回内容一致、`DELETE` → **204**、再取 → 404 |
| 客户端与其它服务 | 11/11 在监听、0 失败；webdav 本机端口仍是 18005 |
| 网关 | `nginx -t` 通过后 reload；线上配置与仓库副本逐字节一致 |

## 踩过的坑

1. **我自己把文档改回了旧版**：先编辑了工作区的 `skills/sso-gateway/SKILL.md`，随后按"仓库 → 工作区"的方向
   拷贝，把刚写的新内容覆盖成仓库里那份**从没改过**的旧文本 —— 两处一起回退，而且当场没发现。
   **教训：同名文件跨位置保持一致时，同步方向必须固定并写死在一个脚本里，不要手工来回拷。**
2. **探针打错机器**：在 Windows 上 `curl 127.0.0.1:8897` 期待网关响应，得到 `000`；`docker exec` 也从 Windows 执行，
   报 `docker_engine` 找不到。**网关与容器的验证必须在 NAS 上做**（同类错误此前也犯过一次）。
3. **把门户页当成"没设防"**：NAS 上未认证请求 `/volume1/` 与 `/` 返回的是 **200**（路径前缀白名单没有它 →
   `return 418` → `@portal` → Authelia 门户页），而 `/__services` 才是 **302**。**别只看状态码判断"是不是被挡住了"。**
4. `ls /data` 在**宿主**上跑（`/data` 是容器内的路径）→ 得到"条目数 0"的假象；要用 `docker exec nas-webdav ls /data`。

## 后续（同日的第二次收窄：`@` 开头的整类排除）

用户看到 `/volume1` 的列表后说"**这些 @ 的都排除掉**"—— 那一串 `@aiconsole`、`@appcache`、`@appdata`、
`@applog`、`@appstore`、`@comic`、`@exif`、`@FileManager`、`@home`、`@kvm`、`@music`、`@search`…
都是 UGOS 的系统/应用内部目录，而用户数据一律不带 `@`。

于是把原先那条 `--exclude /volume1/@docker/**` 换成整类：

```
--exclude /volume1/@*
--exclude /volume1/@*/**
```

**判据（实测）**：`/volume1` 的 PROPFIND 从 22 项变成 **9 项**，含 `@` 的 **0 个**：

```
.fscrypt  <各数据目录…>  docker  lost+found
```

`/volume1/<媒体目录>/`、`<部署根>/`、`/volume1/<音乐目录>/`、`/home/`、`/home/<用户A>/` 仍 207；
`/volume1/@appstore/` → **404**；同一轮探测 ERROR 仍为 **0**。

> 剩下 `.fscrypt`（UGOS 加密元数据）与 `lost+found`（fsck 目录）两个非数据项**没有**排除 ——
> 用户只说了 `@` 那一类，不擅自扩范围。想一起排掉就再加两条 `--exclude`。

## 后续之二：连 `.fscrypt` 与 `lost+found` 也排掉，顺带试出 rclone 的过滤语义

用户随后说"清掉 .fscrypt 和 lost+found"。这两个只在 `/volume1` 顶层出现（`/home` 下与更深层都没有，实测），
加了四条规则：目录名与 `/**` 各一条。

**做了一次反证，推翻了我自己写在注释里的猜测**：

| 规则 | `/volume1` 列表里还看得见吗 | 直连 `PROPFIND /volume1/.fscrypt/` |
|-|-|-|
| 只写 `/volume1/.fscrypt` | **看得见** | **207（能进）** |
| 再加 `/volume1/.fscrypt/**` | 消失 | **404** |

结论：**rclone 的 `--exclude` 只有 `/路径/**` 那一版真的挡住**；只写目录名等于没写
（我原以为"列表看不到但直连可能命中"，实测是"列表也看得到、直连也进得去"）。注释已按实测改正。

**最终判据（实测）**：`/volume1` 列表 **7 项** —— `<各数据目录…> /
docker`；`.fscrypt`、`lost+found`、`@appstore`、`/etc/` 全部 **404**；
数据目录与 `/home/` 仍 **207**；同一轮探测 ERROR **0**；线上 compose 与仓库副本 sha 一致。

## 遗留风险

- `--exclude /volume1/@docker/**` 是**有意排除**：要翻 docker 镜像层就删掉那一行，代价是那 1410 个悬空链接的报错回来。
- 目录仍是**读写**挂载（要往数据目录里写文件）；`/home` 下各用户目录也在暴露范围内（`<用户A>`、`<用户B>`）。
- 无认证 + 同 `sso-net` ⇒ 同网络其它容器可无凭据读写这两个目录（2026-09-23 明确接受的代价，未变）。
- 只挂了 `/volume1` 与 `/home`：将来若有 `/volume2` 或外接盘要暴露，得往 `volumes` 里加。

## 同日第三次变更：按要求开放全部目录 + 反向排除

用户看到页面后提出："我希望可以开放所有目录包括系统目录，然后我在配置，这样就可以自定义了。"

于是把上一节刚立的**暴露面边界从"挂载"改回"过滤器"**：

| | 上一节（挂载边界） | 这一节（过滤器边界） |
|-|-|-|
| nas-webdav 挂载 | `/volume1` + `/home` | `/`（整个宿主根，读写）+ `/proc` `/sys` `/dev` 空目录掩码 |
| 边界的落点 | 容器里根本没有那些目录 | 容器里有，但 `filters.txt` 只放行勾选的 |
| 能暴露系统目录吗 | 不能（勾不到） | **能**（勾一下就行） |
| 底线 | 挂载 + 网关认证 | 网关认证（谁能改）+ `audit.log`（改了什么都留痕） |

`files-admin` 同时升级为**三态勾选 + 反向排除**：勾了父目录后，再点子目录 = 单独排除它
（"勾 `/volume1`、排除 `/volume1/@appstore`"这种）。生成规则的顺序也随之确定：
**排除 → 放行 → 兜底**（rclone 先匹配先生效，排除必须在前，否则被前面的放行吞掉）。

真机验证：放行 `/volume1`、排除 `/volume1/<媒体目录>` ⇒ `/volume1/<媒体目录>/` **404**、`/volume1/<音乐目录>/` **207**；
恢复成"7 个数据目录 + `/home`"后一切照旧；`/etc/` 仍 404（没勾就不在放行里）。

> `.fscrypt`、`@*`、`lost+found` 不再被硬编码挡住 —— 它们默认不可见**只是因为白名单兜底**，
> 想暴露就勾。这是使用者的明确决定，写在这里免得后人以为是漏的。
