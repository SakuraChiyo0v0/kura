# 2026-09-23 nas-mirror 阶段 2：客户端自动发现服务（新机器零服务配置）

## 起因（用户的判断）

> "这个 nas-mirror 完全不是通用的，换台机器就得重新配……我觉得是不是只需要配置服务端，
> 客户端不需要配置，只需要去拉服务端注册好的服务就行了？"

判断是对的：`config.json` 里真正因机器而异的只有账号密码、`nas_lan_host`、`gateway_port`；
`services[]` 描述的是 **NAS 上有什么**，却要在每台机器上抄一遍。
阶段 1（同日）先把清单暴露出来了，这一轮是客户端侧。

## 做了什么

- **配置只有两个新键**：`discover`（默认 true）、`discover_minutes`（默认 5）。
- **`discover.go`**：拉 `/__services` → 解析 → 把本地没有的服务挂上本机镜像；
  成功后把原始 JSON 缓存到 `%USERPROFILE%\.nas-mirror\discovered.json`，
  启动时先按缓存挂载（服务端不可达也能用）。
- **`registry.go`**：新增"当前镜像了哪些服务"的注册表。原来是启动时固定的切片，
  现在必须能在运行期加服务（这才叫"新服务自动出现"），并且要能并发读（状态页）。
- **`session.go` 加 `GatewayGet`**：向网关**自身**取一个路径（不是某个应用的请求），
  复用现有的链路/Host 规则（局域网直连拨号用局域网 IP、Host 必须是公网域名），
  带上传代持的会话；302/401 视为会话失效、作废重试一次。
- **`main.go`**：把"建服务"抽成 `attach` —— 启动挂载与自动发现**共用同一段逻辑**，
  避免"启动能起、自动发现起不来"这种偏差。启动先挂 `services[]`，再按缓存补，最后定期同步。

## 三个刻意的取舍

1. **本地优先**：`config.json` 写过的服务先挂，清单里同名的直接跳过 ——
   用户手写的端口（如 webdav 的 28006，而清单推出的是"未发布"）不会被推导值覆盖。
2. **只增不减**：清单里消失的服务不自动关掉。清单只代表"服务端登记了什么"，
   生成脚本没重跑或临时读不到，都不该让本机正在用的镜像停掉。
3. **拉不到就用缓存**：同步失败只记错误（页面顶行 + `/status.json` 的 `discovery` 段），不动任何在跑的服务。

## 真机验收（标准是"配置里没有的服务自己出现"）

`astrahub` 只在服务端清单里、`config.json` 里**没有**它：

| 检查 | 结果 |
|-|-|
| 冷启动（先删缓存） | 11 个服务、**11 个在监听**；`astrahub` 来源=`discovery`、监听 `127.0.0.1:4310` |
| 真能通吗 | `curl 127.0.0.1:4310` → **401** —— 是 AstraHub 自己的登录页，说明请求真的到了它 |
| 页面 | 多出"服务端发现"分组；顶行写"服务端清单 11 个服务"；名字链接悬停提示"来自服务端清单" |
| `--status` | 多一列"来源"（本地/服务端）+ 清单摘要行 |
| 重启一次 | 11/11 在监听、无重复挂载、无绑定失败（幂等） |
| 日志 | `已按上次的服务端清单挂载 清单服务数=11 新增=1 跳过=0`（只有 astrahub 是新的）✓ |

## 踩过的坑（都由测试/真机抓出来）

1. **只挂上、没启动**：真机上第一次跑出来 `enabled=true / running=false` ——
   `attach` 只负责接上线，启动是调用方的事：启动那批由 main 的循环负责，
   运行期自动发现的这批没人管。修完后 `apply` 自己启动。
2. **每轮同步都新建 runtime**：清单同步是"每轮把所有服务过一遍"，第一版 `attach` 每次都建新 runtime
   并去 `SetEnabled(true)` → 重复绑同一个端口（真机上表现为绑定失败/重复监听）。
   修法：`attach` 先 `registry.Find(服务名)`，已有就复用；`apply` 对已挂上的**一律不动** ——
   顺带保证"用户手动关掉的服务不会被下一轮同步又打开"。
3. **`added` 虚报**：第一版把"早就挂着的"也算新增，日志里一直写"新增 11 个"，
   状态页也一直显示"本轮新增 11"。改成"已挂上的不动、added 只统计真正新挂的"。
4. **测试污染真实端口**：测试里用了 4533/8788 这些**真实服务端口**，而本机正在跑的客户端就占着它们，
   于是"应该挂上 2 个"变成 0 个。改成 `freePort(t)` 拿空闲端口，
   并让测试替身也做成"幂等复用"（与生产实现同形）。

## 遗留风险 / 下一步

- **服务下线不会自动收摊**：清单里删掉的服务仍在本机镜像（按设计），要手动在页面上关掉。
- **本机端口是推导来的**：已发布服务用宿主端口、未发布的退而用容器端口；被占用就跳过并在页面上写明原因。
- 缓存文件 `discovered.json` 与 `services.json` 都以"端口/注册名"为键；改注册名会让状态变成孤儿。
- 还没有"页面上手动添加服务"的入口（阶段 3 候选），也没有"立即重新拉取"按钮。
