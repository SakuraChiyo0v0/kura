# 2026-10-20 数据库安装时可选镜像版本

装数据库时能挑版本了。以前模板把 tag 写死（`postgres:17-alpine` 之类），想装别的只能改代码重发。

---

## 一、怎么做的

**实时查 Docker Hub**（`https://hub.docker.com/v2/repositories/library/<repo>/tags`），
由 **kura-server 去查**（它本来就跑在 NAS 上），客户端只画界面。

没有引入任何依赖 —— 用的是 Node 自带的 `fetch`。

### 为什么不是「内置一份版本列表」

内置的话，出新版本要改代码重发；而 Docker Hub 的 tags 接口是稳定的公开 API。
代价是查的时候要联网，所以做了**离线回退**（见下面「坑 2」）。

---

## 二、踩过的坑

### 坑 1：Sakura UI 的 `SelectField` 不是原生 `<select>`

冒烟里第一版断言写成：

```ts
document.querySelectorAll('[data-testid="db-version-picker"] option').length
```

**我以为是**：0 个选项 = 界面没渲染出来 = 功能坏了。
**实测是**：Sakura UI 的 `SelectField` 是**按钮 + 弹出列表**（`.sk-select-trigger` 与
`.sk-select-option`），根本没有 `<option>` 元素。断言永远得 0。

调试过程中我还据此以为是 React 渲染崩了，加了一堆 `console-message` 捕获 ——
其实一点错都没有，接口也正常返回了 2 个版本（直接 `window.kura.databases.versions('postgres')`
打出来是完整的 JSON）。

**已改成**用项目已有的 `pickSelect` 思路：点 `.sk-select-trigger` 打开、按文字点选项。
**教训**：断言一个组件"渲染出来了"，要先知道它渲染成什么 DOM —— 拿错选择器得到的 0
和"功能坏了"长得一模一样。

### 坑 2：查不到 Docker Hub 不能把安装功能一起废掉

第一版 `listVersions()` 查失败就抛错。那样 NAS 一旦连不上外网（很常见），
整个「安装」页就没法用了 —— 而安装本身**不需要**外网（拉镜像是 docker 干的，
Hub 的 tags API 只是给人挑版本用的）。

**已改成**：失败回 `{ versions: [], error, defaultImage }`，界面显示
「查不到版本（原因），会用默认镜像 xxx」，照样能装。

### 坑 3：官方镜像的 tag 命名**根本不统一**

我以为是 `版本-变体` 一个格式，实测各家都不一样：

| 引擎 | 实际存在的 tag |
|-|-|
| PostgreSQL | `17`、`17-alpine`、`17-bookworm`、`17-trixie` |
| MySQL | `8.4`、`8.0`（**没有 alpine**） |
| MariaDB | `11.4`、`11.4-ubi` |
| Redis | `7`、`7-alpine`、`7-bookworm` |

所以不能用一个统一的下拉。模板里加了 `variants` 字段（这个引擎能选哪些变体），
过滤时按它白名单式地筛 —— **宁可少列，不列一个装不起来的**。

另外**空串（不加后缀的完整版）也是有效变体**：`postgres:17` 与 `redis:7` 都存在。
第一版漏了它，导致下拉里少了最常用的那个 tag（`7` 被当成"变体不在白名单里"滤掉了）。

### 坑 4：镜像名两处写死必然漂移

原来 `compose()` 里直接写 `image: postgres:17-alpine`，模板字段里也有一份 `image`。
第一版加版本选择时只改了字段、没改 compose —— 界面显示选了 16、装出来还是 17。

**已改**：`compose(name, network, image)` 必须接收镜像名，不留默认值。
这样"忘记传"会是一个类型错误，而不是一个静默的错版本。

### 坑 5：镜像名不能直接塞进 compose

`image: ${image}` 那一行最终交给 docker。一个带换行或空格的字符串能在 compose 文件里
**造出额外的行**（比如 `postgres:17\n    privileged: true`）。

**已加** `assertImageName()`：只接受 `仓库:tag` 形状，且仓库必须是这个引擎自己的官方仓库
（换成别的仓库等于换一个我们没验过的镜像）。

---

## 三、过滤规则（宁可少列）

`isListable()` 滤掉的东西与理由：

| 滤掉 | 为什么 |
|-|-|
| 三段版本（`17.2.1`） | 官方镜像的小版本 tag 更新极快、很快被删；钉它没意义，而下拉框会被补丁版本刷屏 |
| `windowsservercore` / `nanoserver` | NAS 是 linux/amd64 |
| rc / beta / alpha | 装上去出问题很难说清是谁的锅 |
| 不属于该引擎 `variants` 的 | 比如 MySQL 不会出现 alpine |

列表按**版本号**从新到旧排（不是按推送时间 —— 老版本偶尔也会重推个补丁）。

---

## 四、没做的

- **镜像变体不做成独立下拉**。用户选的是完整 tag（`17-alpine`），变体已经包含在里面。
  再拆一层出来只会让"版本 × 变体"出现大量非法组合（MySQL 选 alpine 就是空的）。
- **不缓存 Docker Hub 的响应**。查一次几秒钟，缓存反而要处理"过期了怎么办"。
- **不支持自定义仓库**。只认 `library/` 下的官方镜像。

---

## 五、真机验证清单

1. NAS 能连 Docker Hub 时，四个引擎的下拉都能列出真实版本。
2. **选一个非默认版本装出来，`docker inspect` 的 `Config.Image` 确实是它**（这是核心）。
3. NAS 断外网时，下拉显示「查不到版本」，安装仍能成功（用默认镜像）。
4. 点「重新查」能在网络恢复后刷新出来。
