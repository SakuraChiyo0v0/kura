# 2026-10-14 · WebDAV 暴露范围合并成一份，并搬进应用里管

原先范围有两份：NAS 上 kura-server 那份（`state/webdav.json`）和客户端本机 WebDAV 自己那份。
两份同时生效、取交集，谁都可能收窄结果 —— 排查时得同时看两处，而且「文件页看得见、Z: 盘看不见」
这种问题特别难查（文件页走 NAS 那份，Z: 盘走两层）。

现在只有一份：**NAS 那份**。客户端在「文件」页直接读写它，走统一网关的 `/_kura/api/scope`。

## 做了什么

| 位置 | 改动 |
|-|-|
| 服务端 | 加 `/_kura/api/scope`：GET 回 `{limits, defaults}`，POST 整体替换 |
| 客户端 | `session.gatewayRequest`（`gatewayGet` 的通用版，能发 POST）；`core/nas-scope.ts` 解析与自检；IPC `nasScope` 三件套 |
| 界面 | 文件页「本机 WebDAV」拆成三节：本机服务设置 / 暴露范围 / 可见性自检。复用现成的 `RuleList` 与自检视图 |
| 本机 WebDAV | 不再存 include/exclude/readOnly；磁盘上老配置里这几个字段读回来一律丢掉 |

范围层本身没有改动 —— 一直在服务端（rclone 前面那层），只是现在多了个入口能改它。

## 踩过的坑

### 1. 契约写成「合并」，删一条会静默失效 —— 被测试撞出来

我一开始把 POST 设计成**增量合并**（没发的字段保留原值），理由是「两边同时改更安全」。
写完测试才发现这是错的：客户端那页是个**全量列表编辑器** —— 用户看到 `/home`、`/volume1`，
删掉 `/home` 再保存，提交的是「剩下的那些」。合并实现会把 `/home` 又保留下来，**删除静默失效**。

改成整体替换（`include`/`exclude` 都要发全，缺一个回 400 —— 不替客户端猜），并加了一条
断言专门锁住「删掉的条目真的没了」。

教训：**先看调用方是增量式还是全量式，再定契约**。编辑器提交的是最终状态，不是补丁。

### 2. 响应体读错层级：`{limits, defaults}` 我按顶层字段读

服务端回的是 `{ limits: {...}, defaults: {...} }`，我第一版按顶层读 `include`/`exclude`，
结果拿到的是**空范围**。这个错误有个很坏的后果：界面看起来像「范围被清空了」，
用户如果这时点保存，就会把服务端真实的范围覆盖成空。

是单测撞出来的（我断言了具体条目，拿到 `[]`）。这也是为什么这个 bug 值得单测：
纯 TS 类型查不出来（`parseScope` 的返回类型是对的），跑真接口才看得见。

### 3. 老配置文件的 include/exclude 会把 NAS 的范围又收窄一次

本机 WebDAV 原先存过自己的范围。搬家之后如果还把 `webdav.json` 里的 `include`/`exclude` 读回来，
它就会在 NAS 那份之上再裁一次 —— 正是这次要消灭的问题，反而被老文件复活。

改法：构造 `DavServer` 时**显式丢掉**这几个字段（写死成 `davServerDefaults` 的值），
不靠「反正是空的」这种巧合。

### 4. 冒烟里的假 NAS 必须自己扮演范围层

原先冒烟测的是「改本机范围 → 本机 WebDAV 的 HTTP 输出变」。搬家之后如果照旧，
测的就变成「客户端自己算的范围对不对」—— 服务端的裁剪一行都没验到。

所以把假 NAS 改成：**按范围裁列表、也按范围挡直接访问**（真 rclone 前面那层就是这么干的）。
这样「改范围 → 外部程序看到什么」才是真在测服务端契约。
顺带发现我第一版只挡了直接访问、没滤列表 —— 真机上那样就是「列目录还能看到，点进去 404」。

### 5. CDP 截图在窗口被遮挡时会卡死

`Page.captureScreenshot` 在这台机器上不停返回、把命令挂到超时（试了三次）。
原因还是那个老问题：窗口失焦/被遮挡时渲染帧被 Chromium 节流。
`Emulation.setFocusEmulationEnabled` 能让 DOM 尺寸类查询正常，但截图仍然卡。

**这轮所有布局结论都是读 DOM 尺寸得出的，不是看图得出的** —— 我拿不到这个环境里的真实截图。

## 一个没查清的现象（如实记）

验收过程中出现过一张「侧栏整块消失、内容贴到窗口左边」的截图。查不出成因，而且与代码不符：

- `sidebarCollapsed: false`（设置文件与运行中的 DOM 都是），侧栏实测 `x=0 w=232`
- 手动点折叠：侧栏变 **76px**（图标条），不是消失
- 遍历了所有 CSS 规则，没有任何一条隐藏侧栏；也没有对应的媒体查询

**怀疑是「页面骨架已渲染、样式还没到位」的中间态**（HTML 结构本来就是「侧栏 + 主区」两块），
最可能是我这轮反复重启应用时被拍到的。功能上刷新即恢复，未复现第二次。

**没有为了这张图去改 CSS** —— 折叠/展开逻辑本身是好的，没有复现路径就动它风险更大。
若再次出现且刷新不消失，再查。
