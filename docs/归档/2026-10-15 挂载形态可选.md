# 挂载形态可选：硬盘 / 网络位置 / 文件夹

日期 2026-10-15。起因：用户发现「网络位置」里躺着一个点不开的 `Kura Test (\server) (R:)`，
问怎么删。查下去发现根子不在 Explorer，在 Kura 自己。

## 一、那个红叉是怎么来的

它是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\MountPoints2\##server#Kura Test`。

链条是这样的：

1. `ModuleManager.mount()` 一直给 rclone 传 **写死的 `--network-mode`**（老 `mountArgs` 倒数第七行）。
2. `--network-mode` 让 rclone 把卷暴露成 `\\server\<卷名>`，系统当它是网络共享，盘符落在「网络位置」区。
3. Explorer 每访问一次这种共享就记一条 `MountPoints2\##server#<卷名>`。
4. **卸载只卸盘符，不删这条历史**。`net use` 列表空了，那条还在 —— 就成了「网络位置」里一个红叉死图标。

「Kura Test」这个名字来自真机测试 `modules.real.test.ts` 挂盘时设的卷名，所以那条大概率是跑真机测试留下的。

「我以为是 Explorer 抽风 / Kura 没清理干净，实测是 Kura 主动要求了网络模式，而卸载逻辑压根没管注册表」。

## 二、验证过的事实（别当成推测）

- `rclone mount --help`：`--network-mode  Mount as remote network drive, instead of fixed disk drive (supported on Windows only)`
  —— **不加它就是固定磁盘**，这一条决定了整个方案。
- 挂到目录（`folder` 形态）时 rclone 在 Windows 上要求 **挂载点必须不存在**（它自己建、自己删），
  且明确 **不支持与 network 模式同用**。所以 folder 只能是固定磁盘，界面上也不给它网络模式选项。
- Windows 自带 WebDAV 客户端（`WebClient` 服务）这条路**没走**：本机 `WebClient` 是 STOPPED，
  且有单文件 50 MB 上限的坑。rclone 这条已经能用，没必要再开一路。留在 `docs/` 里备查。

## 三、改了什么

三种形态，差别只在 Windows **把挂出来的东西放哪儿**，读写能力完全一样：

| mode | 显示位置 | rclone 参数 | 备注 |
|-|-|-|-|
| `disk`（新默认） | 「此电脑」本地硬盘区 | 不加 `--network-mode` | 程序看不出是远程盘 |
| `network`（老行为） | 「网络位置」区 | `--network-mode` | 卸载时清 MountPoints2 |
| `folder` | 某个目录（如 `D:\KuraNAS`） | 不加 `--network-mode`，挂载点是目录 | 不占盘符；挂载点由 rclone 创建 |

要点：

- `MountSettings` 加 `mode` 与 `folder`；`MountStatus.drive` 改名 `target`（盘符或目录，二选一）。
  **改名是有意的**：留着叫 `drive` 但存目录路径会误导后来的人。
- 默认从「网络位置」改成「模拟成硬盘」。老用户 `mount.json` 里没有 `mode` 字段，
  合并默认值后落成 `disk` —— 也就是说升级后行为会变，这是有意的（固定磁盘才是「挂载为磁盘」的字面意思）。
- `clearNetworkHistory(volumeName)`：只在 network 模式卸载时调，删不掉只记日志，不影响卸载结果。
- 界面用 Sakura UI 的 `FluidSegmented`（`MirrorView` 选「自动/局域网/外网」用的是同一个），
  并给 `.sk-segmented` 覆写成 `grid-template-columns: repeat(3, 1fr)`。

## 四、踩的坑

**布局：FluidSegmented 被塞进 200px 网格列，三个中文标签竖排折行。**
`.kura-module__settings` 是个 `minmax(200px, 1fr)` 的 grid，段选控件默认按内容宽。
第一版截图里「模拟成硬盘」被压成一列一个字。修法：外面包一层 `.kura-module__mode` 并
`grid-column: 1 / -1` 占满整行，再让 `.sk-segmented` 三分列。
**这说明「改完要截图看」，光跑冒烟过不代表界面能看** —— 冒烟只断言了「有父目录字段」，
竖排折行的 DOM 照样满足。

**测试选择器别猜。** 写冒烟时我第一版按 `.sk-el-fluid-segmented`、`role=radiogroup button` 找，
全是错的。去 `node_modules/@sakura-ui/react/dist/index.js` 里搜 `sk-segmented` 才看到真实结构：
`div.sk-segmented[role=radiogroup] > label.sk-segmented-option > input[type=radio]`。
**这个 kit 只发 `.d.ts`，实现是压缩过的 JS，只能搜字符串，不能靠 IDE 跳转。**

**冒烟偶发整片失败和改动无关。** 有一轮 `SMOKE 28/35`、容器页全红还带
`Script failed to execute`，重跑两次又都是 43/43。是并发/时序抖动，不是这次改的东西。
判断依据：失败项集中在容器页，而这次没碰容器。

## 五、没做的

- **没上真机验证 folder 模式**。真机测试 `modules.real.test.ts` 补了 folder 用例，但要
  `KURA_REAL_RCLONE=1` 才跑，联网下载 + 占盘符 + 需要 WinFsp。本机 WinFsp 装了，
  但没在真手上跑这一轮。
- 没做 Windows 原生 WebDAV（`net use`）那条路，理由见上。
