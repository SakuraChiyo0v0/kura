# 2026-10-15 自动更新、更新公告与 GitHub Release 发布（v0.5）

## 做了什么

| 项 | 做法 |
|-|-|
| 发布 | `.github/workflows/release.yml`：推 `v*` 标签 → windows-latest 上 typecheck + 单测 → `electron-builder --publish always`，传安装包、`.blockmap`、`latest.yml`。标签与 `package.json` 版本对不上、CHANGELOG 没这一节就失败（`scripts/release-notes.mjs --tag`） |
| 更新公告 | `CHANGELOG.md` 是唯一来源：发布时抽当前版本那一节写进 Release 正文与 `latest.yml` 的 `releaseNotes`；`build.mjs` 把它拷进 `dist/`，应用里读打包的那份 |
| 自动更新 | electron-updater 6.8.10 + Sakura 的 `createElectronUpdaterBackend` / `createUpdateManager` / `registerUpdaterIpc` / `exposeUpdater`。节奏在 `src/main/updates.ts` 的 `UpdateScheduler`：启动 1 分钟后查、之后每 6 小时；查到就后台下载；下完右下角提示「重启安装」，不点就退出时静默装 |
| 界面 | 设置页「关于与更新」：版本、`UpdateBanner`、本版本更新内容、历次更新内容、自动检查开关。升级后第一次打开弹一次「本次更新内容」（跳过的版本一起列）；全新安装不弹 |
| 不接更新源 | 冒烟永远不接；开发模式默认不接，设 `KURA_UPDATE_URL` 接本机更新源演练。不接时主进程不注册 `sakura:updater:*`，渲染层用 `useKuraUpdater` 换成空实现 |

验证：单测 284 passed（新增 `updates.test.ts`、`changelog.test.ts`）；冒烟 42/42 + 重启 7/7（新增「设置页显示版本与更新内容」「冒烟不接更新源」「新用户不弹」「升级后弹、关掉记下版本」）。

**本机端到端演练**（打包产物，不碰 GitHub）：装 0.5.0 到临时目录 → 本机起一个放 0.5.1 的 `latest.yml` + 安装包的 HTTP 源 →
检查 → 下载（差量失败自动退回全量）→ 右下角提示 → 点「重启安装」→ 安装器无人值守装完、带 `--updated` 拉起新版本，`Kura.exe` 版本变成 0.5.1。
**GitHub 那一段没跑过**：要等第一次真发版（0.5.0 发出去后，再发一个 0.5.1 才算真正验完）。

## 踩过的坑

### 自动更新停在「为谁安装」那一页

我以为 `perMachine: false` 就是「只装当前用户、不问」，实测 assisted 安装器（`oneClick: false`）仍然带「为谁安装」那一页，
只是默认选「仅为我」。手动装没什么，**自动更新**拉起安装器时 electron-updater 只传 `--updated --force-run`，
这一页只认 `/allusers`、`/currentuser` 才跳过，于是更新停在这页等人点。

修法：`assets/installer.nsh` 的 `customInstallMode` 钩子里，`isUpdated` 时按 `initMultiUser` 已经从注册表定好的
`$installMode` 强制选上（`all` 就照常弹 UAC）。全新安装不受影响，仍可选。

### 本机已经有一份「为所有用户」装的 0.4.0

演练时第一次静默安装返回 1223（用户取消了 UAC）。不是安装包坏了：本机 `HKLM` 下已有 0.4.0 的安装记录（`C:\LocalSpace\GithubTools\Kura`），
安装器看到有 per-machine 安装就在静默模式下要求提权。演练改成显式 `/currentuser` 装到临时目录。
演练装、卸的都是 per-user 那份，per-machine 的 0.4.0（注册表、`ProgramData` 开始菜单与 Public 桌面的快捷方式）没被动到。
这台机器上的 0.4.0 没有更新功能，要手动装一次 0.5.0 才能接上自动更新。

### 开发模式下载阶段要 dev-app-update.yml

`setFeedURL` 之后检查能过，下载却要读 `updaterCacheDirName`（打包时写在 `resources/app-update.yml`，开发模式读 `dev-app-update.yml`）。
没有就报错。演练模式下在 userData 里写一份并设 `updateConfigPath`，不往仓库里加文件。

### 不接更新源时渲染层一直报 No handler registered

`useUpdater` 一挂载就调 `getStatus`，冒烟和开发模式下主进程没注册更新通道，每次都在 stderr 打一条。
`appInfo().updatesEnabled` 为假时换成空实现（`src/renderer/use-updater.ts`）。

### 引导页上收不到「已下载」

`UpdateReadyToast` 一开始放在主界面里，还没连 NAS 的人（停在引导页）收不到。挪到 Shell 外面。

### 演练时 npm install 跑进了 node_modules 里

前一条命令 `cd` 进了 `node_modules/@sakura-ui/electron/dist`，`npm install electron-updater` 就装进了那个包自己的 `package.json`。
`npm ci` 恢复时又被正在跑的开发版 Kura 锁住 `electron.exe`（EPERM / EBUSY），要先关掉它；`npm ci` 之后 electron 的二进制要手动
`node node_modules/electron/install.js` 补回来（`allowScripts` 里放行了 electron，但这次没有自动跑）。

### 补记：冒烟窗口放到屏幕外

用户在用电脑时冒烟连跑多轮，窗口一直弹、抢焦点。冒烟默认 `KURA_SMOKE_OFFSCREEN=1`：窗口建在 (-32000, -32000)、`focusable: false`、`skipTaskbar`。
对 Windows 来说它仍是「可见」窗口，「关窗只隐藏」「托盘唤回」这些靠 `isVisible()` 的判据照常成立；
之前加的 `CalculateNativeWinOcclusion` 关闭开关也还在，所以放在屏幕外不会被当成被遮挡而停掉轮询。改完跑一轮 44/44 + 7/7。
规矩写进了 AGENTS.md「工作约定」。

### 坑：CI 上 electronDist 不存在

第一次推标签挂在打包：`The specified electronDist does not exist: ...\node_modules\electron\dist`。我以为 `allowScripts` 放行了 electron，
`npm ci` 就会跑它的 install 脚本下二进制；实测 CI 上没跑（本机那次 `npm ci` 之后也是一样，要手动补）。
工作流里 `npm ci` 之后显式 `node node_modules/electron/install.js`，并检查 `electron.exe` 在不在。
这次失败没建出 Release，删掉远端标签、指到修好的提交上重推。

### 坑：一次发版建出两个同名 Release

重推后工作流是绿的，但 Release 页只有安装包和 `latest.yml`，没有 `.blockmap`。API 一查有**两个** `v0.5.0` Release，blockmap 在另一个里。
electron-builder 是并发上传 `.exe` 与 `.blockmap` 的，两个上传各自查到「Release 不存在」、各建一个。
手动把 blockmap 挪到有 `latest.yml` 的那个、删掉多出来的；工作流改成先 `gh release create` 建好再让 electron-builder 往里传
（它找到已有的、两小时内建的正式 Release 会直接往里传）。**这条修法还没被下一次发版验证过。**

## 补记：真机从 GitHub 自动升级，验通了

装 0.5.0 → 它自己发现 0.5.1 → 后台下载 → 「重启安装」→ 装成 0.5.1.0。日志里 `Install on explicit quitAndInstall` /
`Executing: ...Kura-Setup-0.5.1.exe with args: --updated,--force-run` 齐全，`GithubTools\Kura\Kura.exe` 的版本已是 0.5.1.0。
发版 → 自动更新的整条链路到此闭环。

### 坑：没有新版本时，界面显示「下载更新失败」

升级完之后日志里反复出现：

```
Update for version 0.5.1 is not available (latest version: 0.5.1, downgrade is disallowed).
ERROR 更新 msg="Error: Error: Please check update first"
WARN 下载更新失败 err="Please check update first"
```

根子在 Sakura 那个 electron-updater 后端：它只看 `result.updateInfo.version` 在不在，就当「有新版本」。
electron-updater 在**没有新版本**时不返回 null，而是返回 `{ isUpdateAvailable: false, updateInfo }`，`updateInfo.version` 是**当前版本号** ——
于是被当成「发现新版本 0.5.1」，紧接着下载，electron-updater 拒绝（没查过更新），报 "Please check update first"。
设置页上就是那条红色的「检查更新失败」。

修在自己这层（`src/main/updates.ts` 的 `nsisBackend`）：调 `checkForUpdates()` 后先看 `isUpdateAvailable === false`，是就当没有更新，
其余原样交给 Sakura 的后端。没有改 vendor 包。单测三条钉住：`false` 返回 null、`true` 照常返回版本、上游 `null` 也是没有更新。

**注意**：这个误报只在「已是最新」时出现，所以 0.5.0 上查 0.5.1 一路正常，升级完才暴露出来 —— 也就是说，
不修的话每个装好最新版的用户都会看到一条假错误。
