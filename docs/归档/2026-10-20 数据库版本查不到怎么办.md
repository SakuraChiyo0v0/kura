# 2026-10-20 版本列表查不到：三条路与一条兜底

上一版（0.9.1）加了「装数据库时选版本」，但真机上 `docker.1ms.run` 那句报的是 `fetch failed`。
这篇记排查过程与最后的三条路。

---

## 一、为什么 `hub.docker.com` 连不上

第一版查的是 **Docker Hub 的 web API**：

```
https://hub.docker.com/v2/repositories/library/postgres/tags
```

它有镜像大小、更新时间，字段最全，但**它不是 registry 接口**。

**这是整件事的关键**：国内配的「Docker 镜像加速器」（daocloud、1ms.run、中科大…）
代理的是 **registry 的 `/v2/` 接口**，也就是 `docker pull` 走的那条路。
它们**不会**帮你代理 `hub.docker.com` 那个 web API —— 两者是不同的服务。

所以「给 NAS 配个镜像加速器」这个直觉是对的，但**光配加速器不解决我原来的实现**，
因为我在查另一套 API。必须把查询本身换成 registry 接口。

实测对照（本机）：

| 端点 | 结果 |
|-|-|
| `hub.docker.com/v2/repositories/...` | 200（本机能通） |
| `registry-1.docker.io/v2/...` | ECONNRESET（官方 registry 被墙） |
| `docker.m.daocloud.io/v2/...` | 401 + Bearer challenge（代理了 registry） |
| `docker.1ms.run/v2/...` | 200，直接给 tags |

## 二、三条路

`listVersions()` 现在按顺序试：

1. **配置的镜像站点**（`/v2/<repo>/tags/list`）—— 国内网络下通常只有这条能通
2. **Docker Hub 的 web API** —— 带大小与更新时间，但在国内常常连不上
3. **内置的常用版本列表** —— 两条网络都不通时的兜底

界面按返回的 `source` 说不同的话，用户永远知道自己在看什么。

---

## 三、踩过的坑

### 坑 1：加速器可能**禁掉** tags 列表

`docker.m.daocloud.io` 认证走通了、返回 200，但 body 是：

```json
{"name":"disable-list-tags","tags":[]}
```

**我以为是**：200 + 空数组 = 这个镜像没有版本。
**实测是**：站点明确禁掉了列 tag（只代理拉取，不提供列表）。

如果把这个当成「没有版本」，界面会显示「查不到可用版本」而用户完全不知道为什么。
**已改成**：识别 `disable-list-tags` 这个哨兵值，当一个明确的失败原因，好让上层继续回退。

> 对照：`docker.1ms.run` 直接回 1433 个 tag，不需要认证。

### 坑 2：registry 要 `library/` 前缀

`/v2/postgres/tags/list` 是 403/404，必须写 `/v2/library/postgres/tags/list` ——
官方镜像都在 `library/` 命名空间下。少了前缀整条通道静默失败。

### 坑 3：兜底列表拼的是镜像名，筛子吃的是 tag

`builtinVersions()` 一开始拼成 `postgres:17-alpine` 传给 `selectVersions()`，
而后者期望纯 tag（`17-alpine`）。`splitTag` 认不出带仓库前缀的字符串，整条兜底被筛成空
—— 于是「兜底」本身也是空的，最坏情况依然是「查不到可用版本」。

**教训**：一个函数吃字符串时，「这串东西是什么形状」必须在函数名/注释里写死。
`selectVersions(engine, tags)` 里的 `tags` 是纯 tag，不是镜像名。

### 坑 4：registry 的 tags 是**全量**的，会把下拉框刷满

换到 registry 通道后，PostgreSQL 前 8 个选项是：

```
17.11-alpine, 17.11, 17.11-bookworm, 17.11-trixie,
17.10-alpine, 17.10, 17.10-bookworm, 17.10-trixie
```

光 17 这一个主版本就几十条，用户找不到「17」本身。

**已改成**：同一「主版本 + 变体」只留最新那个，tag 归一到主版本（`17.11-alpine` → `17-alpine`）。

归一到主版本还有个实际好处：`17-alpine` 是官方长期维护的浮动 tag（跟着补丁走），
而 `17.11-alpine` 这种具体小版本很快会被从 Hub 上删掉。

**但「主版本」的定义按引擎不一样**：

| 引擎 | `8.4` 该收成什么 |
|-|-|
| PostgreSQL | `17.11` → `17`（主版本是第 1 段） |
| Redis | `7.2` → `7`（同上） |
| **MySQL** | `8.4` **就是主版本**，收成 `8` 会得到一个不存在的镜像 |
| **MariaDB** | `11.4` 同理 |

所以去重规则由模板的 `majorOf()` 给，不是全局写死一个「取第 1 段」。

## 四、怎么用

「设置 → 数据库 → 镜像站点」填一个加速器域名，如 `docker.1ms.run`，回「安装」页点「重新查」。

**它只影响查版本列表，不改变 docker 拉镜像的行为** —— 后者由 NAS 上 `daemon.json` 的
`registry-mirrors` 决定，是两件事。

填了站点但那个站点禁了 tags 列表（如 daocloud），会继续回退到 Hub、再回退到内置列表，
并且**把每次失败的原因都报出来**，好判断是站点的问题还是 Hub 的问题。

---

## 五、真机验证清单

1. 设置里填 `docker.1ms.run`，回安装页 → 下拉列出真实版本，Banner 说「来自你配的镜像站点」。
2. 不填站点、NAS 连不上 Hub → 下拉列出内置的常用版本，Banner 说「内置的常用版本，不是实时的」。
3. 填一个禁了 tags 的站点（如 `docker.m.daocloud.io`）→ 回退到内置，错误里能看出是「不提供版本列表」。
4. 选一个非默认版本装出来，`docker inspect` 的 `Config.Image` 确实是它。
5. PostgreSQL 的选项里没有 `17.11-alpine` 这种小版本刷屏。
