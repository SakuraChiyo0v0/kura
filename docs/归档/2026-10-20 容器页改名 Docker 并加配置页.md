# 2026-10-20 「容器」改名「Docker」并加配置页

**已变更**：侧栏那一项原来叫「容器」，现在叫 **Docker**（`src/renderer/pages.tsx`）。
页面内容从「只管容器」扩成「NAS 上 Docker 的整体」，多了一个 **配置** tab。

---

## 一、为什么改名

原名「容器」和它的实际内容已经对不上了：

- tab 里有**项目 / 容器 / 镜像 / 卷 / 网络 / 最近操作** —— 镜像、卷、网络都不是「容器」
- 现在又多了一个**配置**（Docker 守护进程的系统信息）

叫「Docker」才是这一页真实的范围。这一页管的是「NAS 上的 Docker」，
数据库那页是它上面的一层应用。

---

## 二、配置页放了什么

**只读的系统信息**（`GET /info` → `DockerEngine.info()`）：

| 字段 | 为什么值得显示 |
|-|-|
| 版本 / API 版本 | 报 bug、查兼容性时要 |
| OS / 内核 / 架构 | 拉错架构的镜像时一眼能看出来 |
| **存储驱动** | overlay2 / vfs —— 换过驱动的话目录结构不一样 |
| **根目录** | 磁盘满了先看这里（NAS 上通常是个大卷） |
| 日志驱动 | 排「容器日志去哪了」时要 |
| **镜像加速器** | 这条最关键，见下 |
| 容器 / 镜像计数 | 一眼看规模 |

**可写的一项**：镜像站点（给 Kura 查版本列表用）。

---

## 三、两条容易混淆的「镜像加速器」

这是这个页面**必须说清楚**的一件事 —— 它们是两个东西：

| | 在哪配 | 管什么 |
|-|-|-|
| NAS 的 `registry-mirrors` | NAS 上 `/etc/docker/daemon.json` | **docker 拉镜像**走哪 |
| Kura 的「镜像站点」 | 这个配置页 | **Kura 查可装版本列表**走哪 |

界面上两者都显示，并明确写「不是一回事」。

**为什么 Kura 不代改 daemon.json**：改它要重启 dockerd，而重启会停掉 NAS 上**所有**容器
—— 包括正在给别的应用用的服务。一个桌面客户端的配置页不该有这种破坏力；
这种操作应该由用户按自己的时间安排在 NAS 上做。所以这一页对守护进程**只读**，
测试里专门有一条断言「只发 GET，没有任何写操作」。

## 四、踩过的坑

### 坑 1：改了侧栏名，冒烟里的导航就失效了

冒烟里 `await nav('容器')` 是按**显示文字**找导航项的。名字改成「Docker」之后，
那一步静默失败（`waitFor` 超时返回 false，后续检查全部连锁失败），表现为：

```
✗ 容器页：项目列表，Kura 自己只读：projects=false
✗ 项目操作：输出实时显示并以成功结束：没有输出面板
✗ 执行异常：Script failed to execute
```

一开始我以为是新加的配置页把渲染搞崩了，加了 `console-message` 捕获 —— **一个错都没有**。
真正原因是导航没找到元素。

**教训**：改一处 UI 文案，要搜一遍**按文字定位的测试**。这类耦合不像类型那样会被编译器抓住。

### 坑 2：让隧道那条冒烟检查更稳

「经隧道打到数据库」那条检查是**一次定生死**（`tcpEcho` 一次，8 秒超时）。
隧道是异步接上的：界面显示地址那一刻，服务端那条 WS 未必已经连到目标。

我加的配置页检查让整轮变长、机器更忙，就把这个临界点碰出来了 —— 三次里挂一到两次。

**已改成**重试 3 轮（每轮间隔 700ms）。真断了的话每轮都会失败，不会假绿。
改完连跑三轮全绿。

> 这一条严格说不是「我引入的 bug」，但**是我让它暴露的**。留着偶发失败的检查比
> 一次假绿更糟 —— 以后真断了会被当成「又在抖」。

## 五、真机验证清单

1. 「Docker → 配置」显示的是 NAS 上真实的 docker 版本与根目录。
2. NAS 上配了 `registry-mirrors` 时，那一栏显示出来；没配时给一句说明。
3. Kura 的「镜像站点」填了值，而 NAS 没配加速器时，界面明确说「你填的这个没配到 NAS 上」。
4. 旧版 kura-server（没有 `/api/info`）上，这一页提示「读不到」但镜像站点仍能填。
