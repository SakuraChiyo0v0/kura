## 踩过的坑

### 1. 整页撑不满窗口：SakuraProvider 多包了一层

截图里侧栏只到窗口一半多（460 / 720）。

- 我以为是 `.sk-sidebar` 自带的 `min-height:100%` 在 flex 父容器里解析不出来，给侧栏加了 `align-self: stretch` —— **没用**。
- 实测布局链：`sk-sidebar:420 < kura-body:420 < kura-app:460 < sk-root:460 < #root:720`。
  断点在 `.sk-root`：**SakuraProvider 在 `#root` 与应用之间插了一个 block 包装层，高度随内容**，
  所以 `.kura-app { height: 100% }` 是相对内容高度算的。
- 修法：`#root > .sk-root { height: 100% }`。之前加的 `align-self` 撤掉（不是原因）。

### 2. 冒烟判据形同虚设，第一次「通过」是假阳性

为上面那个问题加的检查最初写成「侧栏底 == `.kura-body` 底」，结果 **PASS**，可截图明明没撑满。
原因：父容器自己也没撑满，两者底边照样相等。改成对着**视口高度**比，立刻 FAIL 并打出布局链，才定位到坑 1。

——和 NAS-PROJECTS 硬约定 #4 同一件事：判据要能区分「真成功」和「看起来像成功」。
判据的参照物必须是**外部事实**（视口），不能是同样可能出错的相邻元素。

### 3. 小坑

- 标题栏的类名是 `sk-el-titlebar__title`，不是我猜的 `sk-el-title-bar`；`SidebarNav` 的项是带 `aria-label` 的
  `button.sk-sidebar-item`，没有自定义 data 属性。**选择器先去 dist 里查，别猜。**
- TS 7：`declare module '*.css'` 写在有 `import` 的 `env.d.ts` 里会被当成模块增强而不生效，必须单独放在无 import 的 `css.d.ts`。
- `SettingsStore.get` 需要键名（`get('closeToTray')`），全量用 `all()`。
