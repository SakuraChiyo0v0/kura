# 2026-10-16 数据库列表点名字跳到连接信息

## 做了什么

数据库页的列表里，点某个库的名字（`sakura-pg` 那行）直接切到「连接信息」页并把下拉选成它。
以前要先切页、再在下拉里找一遍。名字列从 `<strong>` 换成一个按钮，样式跟概览页可点的服务地址一致
（强调色、悬停加下划线）。

改动落在三处：

- `src/renderer/DatabasesView.tsx`：`DatabasesTab` 多收一个 `onOpenConnect`；
  父组件里 `openConnect(name)` 先 `setSelected(name)` 再 `setTab('connect')`
- `src/renderer/shell.css`：新增 `.kura-db-name__open`，原来是 `.kura-db-name strong`
- `src/main/smoke.ts`：加一条断言，并在隧道那步先点「自动挑一个空闲端口」

## 踩过的坑

### 1. 假 NAS 里没有我以为的那个库

冒烟断言我先写成点 `sakura-mysql`，实际假服务端 `scripts/smoke.mjs:250` 只登记了三个：
`smoke-pg` / `sakura-pg` / `smoke-redis`。而且列表默认选中第一个（`smoke-pg`），
所以要点一个**跟默认不同**的，断言才算真的验证了「跳过去的是我点的那一个」。
最后用 `smoke-redis`——它同时满足「不是默认选中项」和「不跟后面 sakura-pg 那步抢目标」。

### 2. 隧道那两步挂掉，跟本次改动无关

第一次跑冒烟 63/65：新加的断言过了，反而后面「隧道开在本机回环上」和「经隧道打到数据库」挂了。
看截图才发现是 `改隧道失败 本机端口 127.0.0.1:15432 绑定失败: EADDRINUSE`。

查占用：

```
netstat -ano | grep 15432
# TCP 127.0.0.1:15432 LISTENING 39492
```

39492 是 `C:\LocalSpace\GithubTools\Kura\Kura.exe --updated`——**用户自己那份真实安装的 Kura**
（10:00:08 启动，比我这次冒烟早 8 分钟），它握着 postgres 隧道的默认端口 15432。

我以为是 A（我的改动弄坏了隧道），实测是 B（本机真跑着另一个 Kura 占着默认端口）。
这也解释了为什么之前几次冒烟一直是绿的：**用户以前没同时开着 Kura**。

修法是让冒烟先点界面上的「自动挑一个空闲端口」，不再依赖 15432 恰好空着。
这既绕开了占用，又是用户真会走的一条正常路径（比硬编码另一个端口更贴近现实）。

**没有去动用户那个进程**。它不是孤儿，是他正在用的程序。

### 3. 选择器文本不能写死

断言要确认「跳到了 smoke-redis」，但选择器里显示的其实是 `smoke-redis（Redis）`。
如果断言写 `textContent === 'smoke-redis'` 会假失败。改成只判 `includes(target)`，
不去规定「名字（引擎）」这个拼法——那是 UI 文案，不该被测试钉死。
